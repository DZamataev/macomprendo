# Plan 1 → later plans: carryover notes (from final whole-branch review, 2026-08-24)

Read this when executing Plans 2–5. Each item names the plan that must absorb it.

- **Plan 3 (Task rewriting AppModel):** `AppModel.init` must call `persist()` after a successful
  `Settings.migrate` AND after the corrupt-payload fallback — property observers don't fire in
  init, so a migrated/repaired document is otherwise only written back on the next user change.
  Plan 1's shipped code has this latent gap; do not copy it forward.
- **Plan 3 (General settings):** `GeneralTab.setLaunchAtLogin` calls `SMAppService` directly — a
  deliberate foundation-only shim marked with a "PLAN 3 REPLACES THIS" comment. Replace with a
  `LaunchAtLoginManaging` protocol + impl, and make the toggle reconcile with
  `SMAppService.mainApp.status` (today it lies if the user removes the login item in System
  Settings).
- **Plan 3 (HUD):** `Icon.nsImage(for:size:)` re-decodes the SVG on every render. Fine for menus;
  add a small static cache before the HUD renders icons at animation rates.
- **Plan 5 (scripts):** `run()` in scripts/lib/run.mjs now surfaces `signal`; `{check:false}` call
  sites (notarization polling, spctl) must check `result.signal`/`code === null`, not just code 0.
- **Plan 5 (smoke test):** `SystemKeychainStore`'s SecItemUpdate/SecItemAdd fallback is untested in
  CI (deliberate — flaky); add "enter + change an API key in Settings ▸ Providers" to SMOKE_TEST.
- **Plan 5 (scripts tests):** `syncIcons` side-effect paths (missing source, stale removal, licence
  copy) have no automated tests; `--check` also doesn't verify LICENSE-phosphor.txt. Add a
  mkdtemp-based test when touching scripts/.
- **Human smoke test still owed for Plan 1** (headless session couldn't verify): menubar icon +
  menu contents, Settings window shows the Phosphor gear (not SF fallback), launch-at-login toggle
  registers, settings persist across relaunch.
