# Контрольная диктовка для проверки словаря

Дата: 2026-09-14. Цель — узнать, **в какой пропорции** ломается жаргон:
кириллизация (`TextEditor` → `текст-эдитор`) против подмены латинского слова
(`auto-till-dry` → `Auto-Tilt-Dry`). От ответа зависит, что строить первым.

## Как проводить

1. Словарь **выключен** (его ещё нет — просто обычная диктовка).
2. Модель и язык — те, что стоят каждый день. Запиши какие.
3. Читать вслух в обычном темпе, не по слогам и не «диктуя для машины».
   Произноси термины так, как произносишь их в разговоре.
4. Один проход. Результат целиком вставить в раздел «Что получилось» ниже,
   ничего не исправляя.

Абзацы независимы — можно диктовать по одному, с паузами.

## Выводы

1. **Кириллизация — не главная беда (9 %).** Разворот из Q26-bis был преждевременным: при
   `transcriptionLanguage = ru` модель почти всегда пишет термин латиницей. Таблица кириллических
   форм нужна, но четвёртым приоритетом, а не первым.
2. **Доминирует орфография: регистр 39 % + разбиение 16 % = 55 %.** Модель **услышала верно** и
   записала в неправильной форме. Это не задача для биасинга: `NVM` и `nvm` — один и тот же выбор
   декодера, разошлись только начертанием. Лечится детерминированной нормализацией по совпадению
   без учёта регистра, пробелов, дефисов и точек: `Xcode build`, `xcodebuild`, `XcodeBuild` → все
   к канонической форме.
3. **Подмена (18 %) — то, что действительно чинит биасинг.** `jq`→`GQ`, `ruff`→`RAV`,
   `rn-core-lite`→`Rancor Lite`, `MatchHUD`→`Match Hut`. Восемь случаев из 44.
4. **Провал на двухбуквенных.** `jq` и `ruff` — единственные подмены среди коротких команд, и обе
   там, где у слова нет опоры в контексте. Аббревиатуры длиной 2–3 символа модель почти всегда
   пишет капсом, но верными буквами — то есть их спасает нормализация, а не биасинг.
5. **Пропуск целого куска** («В питоновом репозитории поставил всё» → «Теперь поставил все») —
   словарь такое не лечит вообще. Отдельный дефект, вне этой работы.
